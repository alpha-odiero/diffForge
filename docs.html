How the tool parses JSON, compares documents, generates difference paths and presents results.

Getting started

DiffForge is a browser-based utility for comparing two JSON documents. It is built for inspecting API responses, configuration changes, fixture updates and any other structured data where you need to know exactly what changed.

It solves a specific problem: JSON is hierarchical, so a plain text diff often shows large blocks as changed when only one nested value actually moved. DiffForge parses both documents and walks their structures, producing precise difference paths such as $.user.role or $.items[2].price.

Compare two documents

  1. Paste or type the baseline document into the Original JSON editor.
  2. Paste or type the new document into the Updated JSON editor.
  3. Choose Compare JSON. The shortcut is Ctrl/Cmd + Enter.
  4. Review the summary, then filter, search or expand the nested results.
  5. Copy an individual path, copy the report, or download it as a text file.

Editors are validated as you type. A valid document shows a green status; invalid JSON shows the error line and column in the editor footer. Comparison will not run until both editors contain valid JSON.

Reading the results

  • Added means the property or array element exists only in the updated document.
  • Removed means it exists only in the original document.
  • Modified means it exists in both documents with a different value or type.
  • Unchanged means both parsed values are identical.

Difference paths start at $, which represents the root value. Object keys use dot notation when possible, for example $.profile.name. Keys containing spaces, dots or other non-identifier characters use bracket notation, for example $["delivery.window"]. Array positions use index notation, for example $.items[0].sku.

The summary counts difference entries. An added object or array is counted as one added property, not once for every nested value. A missing property is different from a property whose value is null: missing produces an added or removed entry, while null is a real value displayed as null.

Try the built-in examples from the Load example selector on the compare page. Five samples cover user profiles, API responses, product catalogues, configuration files and nested edge cases.

Features

Comparison

  • Recursive comparison of deeply nested objects.
  • Arrays compared by index, including additions and removals at the end.
  • Added, removed, modified and unchanged value detection.
  • Type-sensitive comparison: the number 1 and the string "1" are different.
  • Correct handling of null, booleans, numbers, strings, empty objects and empty arrays.
  • Meaningful JSONPath-style difference paths and a change summary.

Results and navigation

  • Side-by-side original and updated values.
  • Expandable and collapsible nested structures with Expand all and Collapse all controls.
  • Filter by All, Added, Removed, Modified or Unchanged.
  • Search by JSON key or difference path.
  • Hide unchanged rows without losing the full summary.
  • Copy any individual difference path.
  • Copy or download a plain-text comparison report.

How comparison works

1. Parsing

Both editors are parsed with the browser's native JSON.parse. The app never uses eval, and it does not use a custom parser that could interpret input as code. A leading UTF-8 byte order mark is ignored.

When parsing fails, the browser's error message is kept, the character position is converted to a line and column, and the result is shown in the editor footer and in the comparison message. Common causes include trailing commas, comments, single-quoted strings, unquoted keys and unfinished arrays or objects.

Each editor accepts up to 5,000,000 characters. Syntax highlighting is paused above 100,000 characters, and line numbers are omitted above 20,000 lines to keep the interface responsive. Comparisons of 200,000 or more combined characters run in a Web Worker when the browser supports module workers.

2. Recursive traversal

The comparison walks both parsed values together:

  • If both values are objects, the union of their keys is compared. Keys are sorted in the output for a stable result.
  • If both values are arrays, the longer length is used and each index is compared.
  • If both values are primitives, they are compared with type-sensitive equality.
  • If the container types differ, for example an object on one side and an array or string on the other, the path is reported as a modified value.
  • If a property is present on only one side, it is reported as added or removed. The presence check uses own properties, so a property with the value null is not treated as missing.

3. Difference paths

The root path is always $. Object keys are appended with dot notation when they are valid JavaScript-style identifiers; otherwise they use bracket notation. Array positions are appended as [index].

Original: {"user":{"name":"Ada","tags":["dev"]}}
Updated:  {"user":{"name":"Ada","tags":["dev","ops"]}}

Added path: $.user.tags[1]
Value:       "ops"
Original: {"delivery.window":"09:00-17:00"}
Updated:  {"delivery.window":"10:00-18:00"}

Modified path: $["delivery.window"]

4. How arrays are compared

Arrays are compared by index, not by searching for a matching object identity. If two objects move from position 0 to position 1, the values at each index are compared and reported accordingly. This is predictable and makes it easy to see where an API response changed, but it is not a sequence-alignment diff.

Original: {"items":["keyboard","mouse"]}
Updated:  {"items":["keyboard","mouse","hub"]}

Added path: $.items[2]
Value:       "hub"

If an array contains objects, each object is traversed recursively. For example, a change to the stock count of the second variant appears as $.products[0].variants[1].stock.

5. Unchanged values

Values that exist in both documents with the same type and value are marked unchanged. Non-empty containers are not counted as entries themselves; their unchanged leaves are counted. Empty objects and empty arrays that exist on both sides are represented as one unchanged entry so they remain visible in the results. If both documents are completely identical, the summary reports the unchanged values and the result message says that no differences were found.

6. What the summary counts

  • Added: one entry for each property or array element that exists only in the updated document. An added object counts as that one property, not one per nested field.
  • Removed: the same rule for values that exist only in the original document.
  • Modified: each primitive value or type mismatch that changed. Containers that merely contain changes are not counted themselves.
  • Unchanged: identical primitive values, plus empty objects and arrays present on both sides.

Filters and search change which rows are shown, not the totals in the summary. Reports omit unchanged entries but include the unchanged total in their summary.

Frequently asked questions

Is my JSON uploaded to a server?

No. Parsing, comparison, filtering, formatting and report generation happen in the browser. The app does not send editor contents to a server and has no backend API.

Does DiffForge store my data?

Editor contents are kept in memory for the current page and are not written to browser storage. The only stored preference is the selected theme, which is saved in localStorage when available. If storage is blocked, the app continues to work without persistence.

How are arrays compared?

By index. Index 0 is compared with index 0, index 1 with index 1, and so on. If the updated array is longer, the extra indexes are reported as added. If it is shorter, the missing indexes are reported as removed. Arrays are not reordered or matched by object identity.

Why is my JSON invalid?

JSON is stricter than JavaScript object syntax. Common problems are trailing commas, comments, single quotes, unquoted property names, undefined, NaN and incomplete brackets. The editor footer reports the line and column. Fix the reported position first, then validate again.

What happens when a property is missing?

A property that exists only in the original is reported as Removed. A property that exists only in the updated document is reported as Added. This is intentionally different from a property whose value is null: null is a present JSON value and will be displayed as null.

Can I compare deeply nested JSON?

Yes. Objects and arrays are traversed recursively to any practical browser-supported depth. Extremely deep documents are still limited by the browser's call stack, memory and the 5,000,000-character editor limit.

Is there a file size limit?

Each editor accepts up to 5,000,000 characters. Comparisons of 200,000 or more combined characters use a Web Worker when supported. Syntax highlighting is paused above 100,000 characters, and line numbers are omitted above 20,000 lines. Very large documents may still feel slower because the browser must parse and render them.

Can I compare files from my computer?

The current version accepts pasted or typed text. There is no file picker. You can open a local JSON file in any text editor and paste its contents into an editor.

Does it work offline?

After the static assets have loaded, comparison runs locally and does not need a network connection. The app does not register a service worker, so reloading a page that is not cached by the browser still requires the files to be available from the host.

Is the tool free?

Yes. It is a free, static developer utility with no account, subscription or tracking script.

Privacy and security

JSON comparison happens locally in the browser. The app does not upload, transmit or persist the documents you paste into the editors.

  • JSON.parse is used for parsing; eval is never used.
  • Untrusted JSON is rendered with DOM text nodes and textContent, not as HTML.
  • Clipboard writes use the browser clipboard API with a selection-based fallback.
  • Downloads are created locally with a Blob URL and are not sent to a server.
  • Theme preference storage is wrapped in error handling so blocked storage does not break the app.

If the app is deployed on a hosting platform, that platform may process standard HTTP request metadata for the static files. The app code itself does not send editor contents anywhere. See the privacy page for the full description of current data handling.

These statements describe the implementation in this repository. They are not a third-party security certification or a guarantee about future changes.

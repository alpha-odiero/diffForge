PRIVACY

Your data stays safe and private.

This page describes what the current implementation stores, sends and processes. It is written to match the code in this repository, not to make claims about a different deployment.

Comparison data

Documents pasted or typed into the editors are processed locally. Parsing uses the browser's JSON.parse; comparison walks the parsed values in memory; results and reports are constructed in the page. The app has no backend API and does not make network requests containing editor contents.

Editor contents are not saved to localStorage, IndexedDB, cookies or the URL. They exist in page memory until you clear the editor, navigate away or close the tab.

If browser storage is unavailable or blocked, reading or writing the theme preference is wrapped in error handling. The app continues to work; the theme simply may not persist.

No analytics or third-party scripts

The repository does not include analytics, advertising, tracking pixels, session recording, external fonts or third-party JavaScript. The interface is built from local HTML, CSS and JavaScript files.

If you deploy the app, the hosting provider may process standard HTTP request metadata, such as IP address, user agent, requested path and timestamps, as part of serving static files. That processing is outside the app code and depends on the host you choose.

Clipboard

Copy actions use the browser's clipboard API. If the API is unavailable or permission is denied, the app tries a selection-based browser fallback. Clipboard contents are handled by the browser and operating system; the app does not receive clipboard contents from other apps.

Downloads

Report and JSON downloads are created locally with a Blob URL. The generated file is passed to the browser's download mechanism. No file is uploaded to the app or a server.

Security-related implementation notes

  • Input is parsed with JSON.parse. The app never calls eval.
  • Untrusted JSON is displayed using DOM text nodes and textContent, not injected as HTML.
  • Clipboard and storage failures are handled with visible error or fallback behavior rather than being treated as success.
  • Very large inputs are capped at 5,000,000 characters per editor and can be compared in a Web Worker.
  • The current version does not use a service worker or background synchronization.

What this page does not claim

This is a description of the app's own data handling. It is not a security certification, an audit or a guarantee about the browser, the operating system, installed extensions, the hosting provider or future versions. Browser extensions and other software running on your device can access page content independently of this app.

Changes

If a future feature adds server communication, analytics, file storage or any other data flow, this page and the documentation must be updated to describe it accurately before that feature is presented as private or local.

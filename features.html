Product highlights

Comparison

Recursive by default

Nested objects and arrays are traversed automatically. You get a path for every meaningful change, not a block-level text diff.

Comparison

Arrays compared by index

Index changes, new elements and removed elements are reported clearly. Objects inside arrays are compared recursively.

Accuracy

Types matter

The number 1, the string "1" and null are distinct values. Missing properties are not confused with null values.

Editors

Syntax-highlighted inputs

Both editors include line numbers, indentation guides, character and line counts, live validation and precise error locations.

Results

Side-by-side review

Compare old and new values in aligned columns. Added, removed, modified and unchanged rows use consistent colors.

Results

Filter, search and collapse

Filter by difference type, search by key or path, hide unchanged rows and expand nested branches only when needed.

Utilities

Format, minify, validate

Clean up a document, reduce it to one line or validate both inputs without leaving the comparison workspace.

Utilities

Copy and download

Copy individual difference paths, copy the full report or download a text report and either JSON document.

Privacy

Local processing

Parsing, comparison and report generation run in the browser. The app does not send pasted JSON to a server.

Comparison model

DiffForge reports entries at stable, readable paths. The table below shows how each case is treated.

CaseResultExample path
Key exists only in the updated documentAdded$.user.role
Key exists only in the original documentRemoved$.user.location
Primitive value differsModified$.preferences.notifications
Number and numeric stringModified$.count
Property removed versus value set to nullRemoved versus Unchanged$.notes
Array element at the same index changesModified$.items[1].price
Updated array is longerAdded$.items[3]
Updated array is shorterRemoved$.items[4]
Non-identifier keyReported with brackets$["delivery.window"]

An added or removed object counts as one entry for the property that was added or removed; its nested contents are shown as part of that value. Containers that exist on both sides are traversed and their changed leaf values are counted. The comparison documentation explains the traversal and counting rules in detail.

Performance guardrails

  • Comparisons below 200,000 combined characters run on the main thread.
  • Larger comparisons use a module Web Worker when supported, with a main-thread fallback.
  • Syntax highlighting is paused above 100,000 characters per editor.
  • Line numbers are omitted above 20,000 lines to avoid creating an excessive number of DOM nodes.
  • Each editor is limited to 5,000,000 characters and shows an explicit error if the limit is exceeded.
  • Nested results are collapsed by default for very large comparison trees.

Keyboard-first workflow

Compare with Ctrl/Cmd + Enter, format with Ctrl/Cmd + Shift + F, swap inputs with Alt + S and move between editors with Alt + 1 and Alt + 2. The full list is in the shortcut reference.

Deployment

The application is static HTML, CSS and vanilla JavaScript. It does not require a server runtime, database or build step and can be deployed to Cloudflare Pages, GitHub Pages, Netlify or any static file host.

ABOUT

A small tool for a precise job.

DiffForge exists to answer one question quickly: what changed between these two JSON documents?

Open the comparison tool Read the documentation

Why it exists

JSON is everywhere in modern development, but raw text diffs are a poor fit for hierarchical data. A single changed property can shift indentation, move a comma and make an otherwise identical response look noisy. DiffForge parses both sides instead of comparing characters. That makes changes explicit, gives each one a path and keeps the shape of the document visible.

The app is intentionally a utility rather than a platform. It opens directly into the comparison workspace, keeps the controls close to the data and avoids accounts, dashboards and unnecessary setup.

Principles

  • Local by default. Comparison runs in the browser. Editor contents are not sent to a backend.
  • Correct before clever. Native JSON parsing, type-sensitive equality and explicit treatment of missing values are more important than guessing intent.
  • Readable results. Stable difference paths, side-by-side values and consistent status colors make changes easy to scan.
  • Small surface area. Vanilla HTML, CSS and JavaScript with no runtime dependencies and no build step.
  • Honest limits. The application explains its size limits, array model and large-input behavior rather than hiding them.

Architecture

The project is a static site split into small ES modules. Each module has one clear responsibility, and the comparison logic has no DOM dependencies, which allows it to run either on the main thread or inside a Web Worker.

ModuleResponsibility
js/parser.jsNative JSON parsing, validation, error locations, formatting, minification and size limits.
js/comparator.jsRecursive comparison, difference tree construction, paths and summary counts.
js/renderer.jsSummary cards and the accessible, expandable side-by-side result table.
js/editor.jsEditor state, validation feedback, counts, line numbers and scroll synchronization.
js/highlighter.jsSafe DOM-based JSON token highlighting and indentation guides.
js/app.jsApplication wiring, utilities, filters, search, shortcuts and report actions.
js/compare-worker.jsOff-main-thread comparison for large documents.
js/site.jsShared theme persistence, navigation behavior and documentation navigation.
js/samples.jsRealistic sample document pairs.

Technical choices

  • No framework. The interface is small enough that direct DOM construction is simpler to audit and cheaper to load.
  • No dependencies. The app ships its own parser wrapper, highlighter, clipboard fallback and download helper.
  • No backend. There is nothing to deploy except static files.
  • Safe rendering. User JSON is inserted with text nodes and textContent. The app never uses eval or renders untrusted strings as HTML.
  • Progressive performance. Small comparisons run immediately; large comparisons can move to a Web Worker; very large editor features are deliberately reduced to protect the main thread.

Limitations

  • Arrays are compared strictly by index, not with a sequence-alignment algorithm or object-identity matching.
  • Keys are sorted in the comparison output for deterministic results.
  • Editor contents are not persisted between page loads.
  • Each editor is limited to 5,000,000 characters; extreme nesting is still constrained by the browser call stack and available memory.
  • The current version does not provide a file picker or multi-document comparison.
  • Large results are collapsed by default and can still be expensive to expand if the diff contains tens of thousands of entries.

Privacy

The app does not upload editor contents, does not use analytics scripts and does not require an account. The only stored preference is the selected theme. See Privacy for the complete description and the documentation for implementation notes.
